# ksctl v0.3.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare and publish ksctl `v0.3.0` from `main` through the existing GitHub Release workflow.

**Architecture:** The repository remains tag-driven: release documentation is committed and pushed to `main`, an annotated `v0.3.0` tag identifies that exact commit, and the existing Release workflow verifies and publishes GoReleaser artifacts. Local test and build gates are intentionally omitted; remote CI and the tag-triggered workflow provide the executable verification.

**Tech Stack:** Git, GitHub CLI, GitHub Actions, GoReleaser, Markdown

## Global Constraints

- Publish the complete current `main` delta since `v0.2.0`.
- Use release date `2026-07-31`.
- Do not change Go behavior, dependencies, supported platforms, workflow permissions, or archive layout.
- Do not run local tests, `make verify`, `goreleaser check`, or a GoReleaser snapshot build.
- Do not create or commit `bin/` or `dist/` artifacts.
- Use annotated tag `v0.3.0`.
- Never move or recreate the published tag if the Release workflow fails.

### Task 2: Preflight and publish the release commit

**Files:**
- Inspect only: repository and remote Git state

**Interfaces:**
- Consumes: the committed release documentation from Task 1
- Produces: an aligned and CI-verified `origin/main` release commit suitable for tagging

- [ ] **Step 1: Confirm local repository state and GitHub authentication**

Run:

```bash
git status --short --branch
git branch --show-current
gh auth status
```

Expected: a clean `main` branch that is ahead of `origin/main` only by the
approved release documentation commits, and authenticated GitHub access.

- [ ] **Step 2: Refresh remote refs and reject an existing release tag**

Run:

```bash
git fetch origin main --tags
git ls-remote --exit-code --tags origin refs/tags/v0.3.0
```

Expected: fetch succeeds and `git ls-remote` exits with status `2`, meaning
the exact remote tag does not exist. Any matching remote tag stops the
release.

- [ ] **Step 3: Confirm the local branch is based on current remote main**

Run:

```bash
git merge-base --is-ancestor origin/main main
git log --oneline --decorate origin/main..main
```

Expected: `origin/main` is an ancestor of local `main`, and the displayed
commits are only the approved design and release-preparation commits.

- [ ] **Step 4: Push the release commits**

Run:

```bash
git push origin main
```

Expected: `origin/main` advances to the local release commit.

- [ ] **Step 5: Confirm local and remote commit alignment**

Run:

```bash
git rev-parse HEAD
git ls-remote origin refs/heads/main
```

Expected: the two commit IDs are identical.

- [ ] **Step 6: Wait for CI on the exact release commit**

Resolve the release commit and find its CI run:

```bash
release_commit="$(git rev-parse HEAD)"
ci_run_id=""
for attempt in {1..12}; do
  ci_run_id="$(
    gh run list --workflow CI --branch main --commit "$release_commit" \
      --event push --json databaseId --limit 1 --jq '.[0].databaseId'
  )"
  test -n "$ci_run_id" && break
  sleep 5
done
test -n "$ci_run_id"
gh run view "$ci_run_id" \
  --json databaseId,status,conclusion,headSha,url
```

Confirm the returned `headSha` equals `release_commit`. Then run:

```bash
gh run watch "$ci_run_id" --exit-status
```

Expected: the CI run for `release_commit` finishes successfully. A missing,
failed, cancelled, or timed-out run stops the release before tagging.

### Task 3: Create and push the annotated release tag

**Files:**
- Inspect only: Git refs and release commit metadata

**Interfaces:**
- Consumes: the aligned, successful release commit from Task 2
- Produces: remote annotated tag `v0.3.0`, triggering the Release workflow

- [ ] **Step 1: Reconfirm the tag target and absence**

Run:

```bash
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"
git ls-remote --exit-code --tags origin refs/tags/v0.3.0
```

Expected: branch commits match and the tag query exits with status `2`.

- [ ] **Step 2: Create the annotated tag**

Run:

```bash
git tag -a v0.3.0 -m "v0.3.0"
git for-each-ref refs/tags/v0.3.0 \
  --format='%(refname:short) %(objecttype) %(subject)'
git rev-list -n 1 v0.3.0
git rev-parse HEAD
```

Expected: `v0.3.0` is a tag object with subject `v0.3.0`, and its peeled
commit equals `HEAD`.

- [ ] **Step 3: Push only the release tag**

Run:

```bash
git push origin refs/tags/v0.3.0
git ls-remote --tags origin refs/tags/v0.3.0 'refs/tags/v0.3.0^{}'
```

Expected: the remote contains the annotated tag and its peeled commit.
