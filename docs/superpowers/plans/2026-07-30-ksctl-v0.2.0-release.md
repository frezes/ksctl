# ksctl v0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare, verify, tag, and publish the `v0.2.0` ksctl release from `main`.

**Architecture:** Treat the release as a documentation-only release cut followed by reproducible local gates. Commit the release metadata first, verify that exact clean commit with the repository and GoReleaser gates, push it to `origin/main`, then create one annotated tag on the verified commit and monitor the tag-triggered GitHub Release.

**Tech Stack:** Go 1.26, GNU Make, GoReleaser 2.17.0, Git, GitHub Actions.

## Global Constraints

- Release version is exactly `v0.2.0`; changelog date is exactly `2026-07-30`.
- Modify only `CHANGELOG.md` and the release installation version in `README.md`.
- Do not change Go code, dependencies, workflows, supported platforms, or archive layout.
- Preserve an empty `Unreleased` section and the existing `0.1.0` history.
- Publish `ksctl` and `unictl-ks` for Linux and macOS on `amd64` and `arm64`.
- Use an annotated tag, matching the existing `v0.1.0` tag style.
- Do not create or push the tag unless every local verification gate passes from the clean release commit.
- Do not move, overwrite, delete, or recreate an existing local or remote `v0.2.0` tag.
- Generated `bin/` and `dist/` artifacts must remain untracked and uncommitted.

- [ ] **Step 1: Replace the Unreleased entries with a dated release**

Keep the `Unreleased` heading empty, then add this section immediately below
it:

```markdown
## [Unreleased]

## [0.2.0] - 2026-07-30

### Added

- Add host-scoped `extension` discovery, exact-version lifecycle management,
  configuration, multicluster placement, waiting, status, and diagnosis.
- Add `auth whoami` to verify the selected KubeSphere credential and display
  the server-side User and global role.
- Add kubectl-compatible `ksctl-*` executable plugins, including longest-name
  dispatch and `plugin list` diagnostics.
- Add `tenant get` commands for KSE Workspaces, Namespaces, and Clusters with
  Workspace and member-Cluster routing plus kubectl-style table output.
- Add kubeconfig generation for the selected KubeSphere Context and Cluster.
- Add kubectl-compatible `logs` and resource-metrics `top` commands.
- Add authenticated raw KubeSphere API requests through `ksctl api`.
- Add the release-only `unictl-ks` companion entrypoint.

### Changed

- Scope `--namespace` to Kubernetes resource commands while preserving
  kubeconfig Namespace defaults.

### Security

- Revoke cached Access Tokens through the KubeSphere logout endpoint on a
  best-effort basis before clearing local login state.
- Bind explicit endpoints to explicit tokens and harden configuration and TLS
  boundaries.
```

### Task 2: Verify the Clean Release Commit

**Files:**
- Verify: `Makefile`
- Verify: `.goreleaser.yaml`
- Verify: generated untracked `bin/` and `dist/` outputs

**Interfaces:**
- Consumes: the clean release metadata commit from Task 1.
- Produces: passing code-quality gates, eight snapshot archives, one checksum manifest, and explicit version-output evidence for both entrypoints.

- [ ] **Step 1: Confirm the worktree and release version**

Run:

```bash
git status --short --branch
git show --stat --oneline HEAD
```

Expected: no tracked or untracked changes and `HEAD` is
`prepare v0.2.0 release`.

- [ ] **Step 2: Run the complete repository verification**

Run:

```bash
env GOCACHE=/private/tmp/ksctl-go-build-cache make verify VERSION=v0.2.0
```

Expected: formatting, module checks, vet, normal tests, race tests, and the
version-injected `bin/ksctl` build all succeed.

- [ ] **Step 3: Validate and snapshot the release configuration**

Run:

```bash
goreleaser check
goreleaser release --snapshot --clean
```

Expected: both commands exit successfully. The snapshot creates four platform
archives for `ksctl`, four for `unictl-ks`, and `dist/checksums.txt`.

- [ ] **Step 4: Inspect snapshot artifacts and checksums**

Run:

```bash
find dist -maxdepth 1 -type f -print | sort
find dist -maxdepth 1 -type f -name '*.tar.gz' | wc -l
test -f dist/checksums.txt
wc -l dist/checksums.txt
```

Expected:

- exactly eight `.tar.gz` files;
- archive names cover `ksctl` and `unictl-ks`, `linux` and `darwin`, and
  `amd64` and `arm64`;
- `dist/checksums.txt` exists and contains exactly eight lines.

- [ ] **Step 5: Verify v0.2.0 linker injection in both entrypoints**

Run:

```bash
go build -trimpath \
  -ldflags '-s -w -X github.com/kubesphere/ksctl/pkg/cmd.version=v0.2.0' \
  -o /private/tmp/ksctl-v0.2.0 ./cmd/ksctl
go build -trimpath \
  -ldflags '-s -w -X github.com/kubesphere/ksctl/pkg/cmd.version=v0.2.0' \
  -o /private/tmp/unictl-ks-v0.2.0 ./cmd/unictl-ks
/private/tmp/ksctl-v0.2.0 version
/private/tmp/unictl-ks-v0.2.0 version
```

Expected: the first line from both commands is
`ksctl Version: v0.2.0`. Server versions may be `unknown` without a configured
reachable server.

Run:


Expected: no tracked or untracked changes; `bin/` and `dist/` are ignored.

### Task 4: Tag and Publish v0.2.0

**Files:**
- Create: annotated Git tag `v0.2.0`
- Remote update: `origin` tag `v0.2.0`
- External output: GitHub Release `v0.2.0`

**Interfaces:**
- Consumes: the verified release commit already present at `origin/main`.
- Produces: one immutable annotated tag and a successful GitHub Release with all configured artifacts.

- [ ] **Step 1: Reconfirm the exact tag target**

Run:

```bash
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"
git status --short --branch
git tag --list v0.2.0
git ls-remote --tags origin refs/tags/v0.2.0
```

Expected: clean synchronized `main` and no local or remote `v0.2.0` tag.

- [ ] **Step 2: Create and inspect the annotated tag**

Run:

```bash
git tag -a v0.2.0 -m "v0.2.0"
git cat-file -t v0.2.0
git rev-list -n 1 v0.2.0
git rev-parse HEAD
```

Expected: the object type is `tag`, and the tag's commit ID equals `HEAD`.

- [ ] **Step 3: Push only the release tag**

```bash
git push origin refs/tags/v0.2.0
```

Expected: `origin` accepts the new tag and the Release workflow starts.
